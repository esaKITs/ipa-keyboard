## 2-1. 記号の視覚的な大きさ

Doulos SIL と Andika の実アウトラインから、ɓ、ɗ、ʍ、ɕ、ʑ のインク外接範囲を計測しました。同じ字形の表示サイズを26.6667pxから32pxに変更したため、縦横とも20%拡大します。両フォントで10組の比較結果を保存しました。フック、ディセンダー、小型大文字、修飾記号には各フォントに収録されているプロポーションを使用しています。肺気流子音、母音、補助記号、超分節音の既存のサイズ指定を維持しました。非肺気流子音は拡大した字形に合わせて行の高さが増えます。

元パスとSVGを比較する検証の許容差は `1e-9` SVG単位です。重ね合わせはグリフに接する線の余白を適用する前の線と黒点を比較します。実際の表示では、選択中のフォントのアウトラインに応じて既存の線の余白が付きます。グリフ自体はDoulos SILまたはAndikaです。

## ブラウザ検証

Chromium 151.0.7922.34 と Playwright WebKit 26.5 で、320・375・393・768・1280px幅を検証しました。5表示言語、日本語・英語・ブラジルポルトガル語・ペルシア語・大阪弁、白黒2モード、Doulos SIL・Andika を組み合わせた200条件で、7本のパス、11点、母音アンカー、235の入力対象の維持と表示領域を確認しました。拡大1×・2×・4×ではSVGの座標変換行列で縦横の倍率を照合しました。各端末幅で代表記号の入力、Undo・Redoを実行しました。

ChromiumとWebKitの追加検証では全7区分の長押しプレビュー、拡大中のジェスチャーによるプレビュー解除、フォント・入力色の変更、Unicodeの保持を確認しました。フォントのフォールバックはChromiumで確認しました。作業ブランチの[GitHub Actions](https://github.com/esaKITs/ipa-keyboard/actions/runs/45776418809)に第1弾の動作、表示、入力パネル、拡大、全体図、復旧のジョブと今回の検証を保存しました。

iPhone・Androidの実機は未検証です。記号検索UIは起点のバージョンに見当たらず、検索操作の検証は該当しません。[第2弾の確認用サイト](https://esakits-ipa-phase2-20261126.esakit.chatgpt.site/)は依頼者のみ利用できます。ログイン前のゲートまで接続し、操作は同一ファイルを配信した検証環境で確認しました。

## 復元方法

第1弾確認済みの状態は `backup/before-phase2-20261126` を新しいテストブランチにチェックアウトして再現できます。第2弾は `backup/after-phase2-verified-20261126` または検証対象のSHAから再現できます。サイト側のパッケージには、第2弾のブラウザ実行に必要な22ファイルを収録し、検証対象コミット内の各ファイルとバイト単位で照合しました。公開版の main と GitHub Pages 配信設定は変更していません。
